# WMS OCR 做单

先按原单类型识别并交付核对表。用户指定目标 WMS、单据类型和操作范围后，再按实际页面或导入模板准备或录入。

## 选择输入文件

- 有明确指定来源时按用户指定。其余情况下优先处理当前消息中的图片、截图或 PDF。技能已在当前任务启用时，仅发送一张附件也按「生成单据草稿」处理，直接识别可见内容。附件已发送但当前客户端无法读取时，告知用户并请其重新附上可读取的文件或提供路径。
- 当前任务没有会话附件、用户也没有指定来源时，读取当前 Windows 用户桌面下的 `ocr识别` 文件夹，可用 `[Environment]::GetFolderPath('DesktopDirectory')` 定位桌面。按文件名稳定排序，批量识别目录第一层的 JPG、JPEG、PNG 和 PDF。目录不存在或没有可识别文件时，告知用户检查的路径并请求提供来源。
- 用户说「识别新增图片」时，以该目录最近一次确认使用的核对表或处理记录为基线。没有可靠基线时照常识别，并标注本轮无法确认历史重复。用户点名的文件始终可单独重跑。
- 为下次增量识别，在输出中保留每个来源文件的名称、SHA-256 和处理结果。文件内容相同且此前已完成的可复用结果，即使改了文件名。文件名相同但内容变化时重新识别，标为新版；上次读取失败或尚未完成的文件仍可纳入本轮。没有文件哈希的历史记录只能用于提示疑似重复。输出放在独立位置，保留原件和既有核对表。
- 按文件记录识别结果、待核对项与读取失败项。跨文件合并须有单号、续页信息或其他原单证据，合并后按行保留原文件名及页码或图中位置。

## 识别原单

1. PDF 有文本层时优先提取文本，并对照页面确认表格列和行。照片及扫描页先校正方向，必要时校正倾斜，再识别。逐行复核盖章遮挡、相邻列错位与模糊单元格。
2. 按原单拆分单头和明细。单头保留资料类型、来源编号、日期、原件注明的单位角色及仓库；明细按原顺序保留编码、品名、规格、数量、重量、单位，以及原件明确给出的批次、生产日期和效期。保留前导零及小数位。提货单、钢材货物清单和加工单的专用规则见[钢材单据核对规则](references/steel-document-review.md)。
3. 对空白、看不清或存在多个读法的字段标为「待核对」，附原文件名、页码及行号或页面位置。将原单的送货数量按其实际含义映射。实收数量以现场收货记录或用户确认值为准。

## 映射与核对

- 根据目标 WMS 的页面或导入模板核实单据类型、必填列、录入格式和可用的主数据。没有模板或访问入口时，先用业务字段整理草稿，在备注中列出仍需确认的映射。
- 优先按编码查找货品、供应商和仓库。仅有名称时，结合规格和单位核对，多个匹配项列为待确认。换算数量时使用系统或用户提供的包装关系，并保留原单数量与单位供复核。
- 对照原单核对明细行数与数量。同单位的数量可汇总对照，单位不同则分别核对。区分来源单号和 WMS 单号。有系统访问权限时，按可用的来源单号、供应商等条件查询已有单据，处理疑似重复后再新增。

## 交付与录入

- 会话里发一张图并说「做单」或「生成单据」时，直接在回复中给出中文单据草稿，包含识别出的单据类型、单头、明细表和待核对项。原件名称不可见时可用「本次附件」及图中位置作为来源。只有用户要求 Excel、指定导入模板或进行目录批量处理时才生成相应文件。
- 核对表包含单头、逐行明细、来源与待核对项。增量结果说明新增、变更、复用和失败文件。用户提供导入模板并要求生成导入草稿时使用其原有列名和格式。
- 用户要求实际录入时，使用指定 WMS 已有的录入或导入功能。保存前确认必填字段和关键映射。按用户授权执行相应操作，提交、审核或过账须在授权范围内。保存后回查 WMS 单号、状态和明细。结果不明或批量导入部分失败时，先查已写入记录，再处理失败项。
